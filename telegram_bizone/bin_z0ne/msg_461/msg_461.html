 macOS Security: как работает Gatekeeper

macOS все чаще становится целью стилеров, троянов и ClickFix-кампаний. При этом встроенная модель защиты Apple хотя и затрудняет, но не полностью лишает атакующих возможности первоначального доступа.

В этом посте рассмотрим подробнее, как работает механизм Gatekeeper, отвечающий за контроль доверия к запускаемому ПО, и что делают атакующие, чтобы его обойти.

Это первый пост из серии постов о macOS, в которых мы расскажем обо всех этапах цепочки атаки на эту ОС. Все следующие посты будут выходить под тегом #macos

Перед тем как перейти к Gatekeeper, опишем, что из себя представляет карантин в macOS.

macOS Quarantine

Файлы, полученные из внешних источников, могут получать extended attribute: com.apple.quarantine. Атрибут выставляется, если файл загружен приложением, являющимся FileQuarantine-Aware (LSFileQuarantineEnabled: YES в Info.plist). Такими приложениями являются браузеры, почтовые агенты, торренты и т. д.

В macOS есть список идентификаторов, где LSFileQuarantineEnabled перезаписывается на yes по умолчанию, он находится по пути /System/Library/CoreServices/CoreTypes.bundle/Contents/Resources/Exceptions.plist.

Plain text

Формат com.apple.quarantine:
<Flag>;<Timestamp>;<Agent>;[UUID]

Flag:
  0081 = Quarantine applied, Gatekeeper assessment required.
  0082 = Assessment performed (Gatekeeper passed). Subsequent
         launches skip assessment.
         
Timestamp:
  Hex-encoded Unix epoch seconds.
  
Agent:
  Bundle ID или исполняемый файл, который загрузил файл.
  Safari, Chrome, com.apple.mail, curl, Firefox, etc.
  
UUID (optional):
  Уникальный идентификатор для отслеживания события карантина.

Проверить его можно одной из команд:
 - `xattr -l Application.app`
 - `xattr -p com.apple.quarantine Application.app`


Gatekeeper

Будет ли файл проверяться Gatekeeper, зависит от:

  • Формата файла.
  • Был ли файл загружен из внешних источников.
  • Способа запуска файла.

Что важно помнить

Если файл запущен из терминала (прямой вызов execve, а не через LaunchServices), Gatekeeper НЕ срабатывает независимо от состояния карантина.

Gatekeeper Bypass

Зная поведение Gatekeeper, можно выделить несколько техник его обхода:

  1. 1.
    Right-click Open

    Пользователь открывает файл через нажатие правой кнопки мыши → open. Это приводит к появлению диалога, в котором пользователь может запустить файл (вместо явного отказа). Это является ожидаемым поведением системы и работает, если у файла есть валидная подпись (ad-hoc подписи достаточно на некоторых версиях, на других требуется Developer ID).

  2. 2.
    Quarantine xattr Removal

    xattr -d com.apple.quarantine /path/to/app
    xattr -c /path/to/app (удаляет все xattr).

    Без карантина проверка Gatekeeper не осуществляется. Приложение запустится, даже если оно не подписано. Это наиболее распространенная техника, так как она требует только прав write на файл, членство в группе admin не обязательно.

  3. 3.
    Quarantine Flag Flipping
    xattr -px com.apple.quarantine /path/to/app | xxd -r -p | sed 's/^0081/0082/' | xxd -p | tr -d '\n' | xargs -I{} xattr -wx com.apple.quarantine "{}" /path/to/app

    Изменение флага с 0081 «Требует проверки» на 0082 «Прошел проверку» сделает так, что проверка Gatekeeper для файла не запустится.

  4. 4.
    Terminal Execution (LaunchServices bypass)

    /path/to/Quarantined.app/Contents/MacOS/executable

    Даже если у .app-бандла есть атрибут карантина, таргетированный запуск исполняемого файла из терминала обойдет проверку Gatekeeper.

Обход механизма Gatekeeper — важный этап в цепочке атак на macOS. Наиболее интересным для атакующего вариантом первоначального доступа и выполнения кода служит формат .pkg (спойлер: он дает атакующему возможность выполнения кода от root).
