🤔 **Детектируем TLS-туннели без расшифровки**

TLS давно стал идеальным укрытием: снаружи мы видим лишь безобидный шифрованный поток, а внутри вполне может жить полноценный C2-туннель. Мы уже [показывали](https://bi.zone/ru/expertise/blog/zloumyshlenniki-ekspluatiruyut-uyazvimost-cve-2025-55182-v-atakakh-na-rossiyskie-kompanii/), что Sliver встречается в реальных цепочках атак. Ниже — разбор, как детектировать такие невидимые TLS-туннели без расшифровки.

Начиная с версии Sliver 1.7.0 в mTLS-транспорте используется Yamux — легкий протокол мультиплексирования, который позволяет гонять несколько логических потоков поверх одного TCP-/TLS-соединения. Yamux добавляет служебные кадры и предсказуемую «структуру» обмена, и в связке с сообщениями Sliver это дает хороший материал для сигнатур.

**Порядок сообщений (клиент → сервер) после установки TLS-сессии**

**1️⃣****Yamux preface**: MUX/1 — длина TLS Application Data record (ciphertext): **22**.

2️⃣**Yamux frame header**: WINDOW_UPDATE — длина TLS Application Data record (ciphertext): **29**.

3️⃣**Yamux frame header**: DATA — длина TLS Application Data record (ciphertext): **29**.

4️⃣**DATA payload**: RawSig (EdDSA + keyID публичного ключа подписи + ed25519 signature) — длина TLS Application Data record (ciphertext): **91**.

5️⃣**Yamux frame header**: DATA — длина TLS Application Data record (ciphertext): **29**.

6️⃣**DATA payload**: uint32 LE длина следующего protobuf-Envelope — длина TLS Application Data record (ciphertext): **21**.

7️⃣**Yamux frame header**: DATA — длина TLS Application Data record (ciphertext): **29**.

8️⃣**DATA payload**: protobuf Envelope (MsgRegister) → Register{ метаданные хоста/процесса и активного C2 } — длина TLS Application Data record (ciphertext): **переменный** (часто в диапазоне сотен байт).

После первичной регистрации имплант раз в 2 минуты отправляет keepalive-ping для проверки доступности C2. Типичная «форма» ping по длинам TLS Application Data record (ciphertext): **21 → 29 → 25** (повторяется несколько раз).

**Общая логика сигнатуры**

1️⃣Поймать init-цепочку TLS records с длинами ciphertext:

**22 → 29 → 29 → 91 → 29 → 21 → 29 → (200–600)**

2️⃣Затем подтвердить сессию несколькими ping-последовательностями:

**21 → 29 → 25** (2–3 раза в пределах окна времени)

Даже без расшифровки TLS Sliver остается заметным: mTLS-сессии с Yamux дают стабильную сигнатуру по последовательности размеров TLS records и характерным ping-пакетам. Корреляция init-цепочки и периодических ping позволяет уверенно атрибутировать C2-трафик и снизить число ложных срабатываний.
