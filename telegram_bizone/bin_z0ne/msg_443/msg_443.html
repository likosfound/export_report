Как атакующие обходят WAF: command injection

В прошлый раз мы обсуждали обход WAF через загрузку web shell, сегодня разберем еще один популярный вектор — command injection — и техники его обхода.

Как WAF детектит command injection

Большинство WAF анализируют HTTP-запросы по нескольким направлениям:
Детектирование специальных shell-символов и операторов.
;, |, &, &&, ||, $(), `, \n
Поиск ключевых команд по сигнатурам (blacklist).
cat, ls, whoami, id, nc, bash, sh, python, perl
Анализ конкатенации строк и подозрительных паттернов.


Пример уязвимого кода

Представим веб-форму, принимающую IP для ping:

PHP

<?php
$ip = $_GET['ip'];
system("ping -c 4 " . $ip);
?>

Очевидная эксплуатация вроде той, что представлена ниже, будет моментально заблокирована современным WAF:
; cat /etc/passwd
| whoami

Техники обхода
1. Использование малораспространенных утилит

Некоторые команды редко фигурируют в сигнатурах:
vmstat, uptime, lsblk, findmnt, mktemp, ss, vdir, tempfile, lscpu, lsmem,
uname, date, free, w, lastlog, stat, du -sh, lsattr, file, dig @ localhost.

Они не выглядят как «классическая атака», но позволяют получить:
• загрузку CPU и памяти;
• структуру файловой системы;
• сетевые соединения;
• информацию об оборудовании.

WAF может не триггернуться, а атакующий уже собирает разведданные.

2. Обфускация через конкатенацию строк

Конструкция "h""o""s""t""n""a""m""e" или "l""a""s""t" интерпретируется оболочкой как единая команда hostname и last соответственно, в то время как для WAF это может выглядеть как набор безобидных строк.
Аналогично работает и с другими командами.

3. Косвенное чтение файлов

Вместо прямой команды cat, которая гарантированно блокируется, применяются альтернативные методы доступа к содержимому файлов:

• od -c /etc/passwd
Выводит содержимое указанного файла в виде восьмеричных кодов и соответствующих им печатных символов.

• rev /etc/passwd
Переворачивает строки. Полученные данные легко восстановить.

• cut -d: -f1 /etc/passwd
Извлекает только имена пользователей — минимум шума, максимум пользы.

4. Комбинирование легитимных утилит для взаимодействия с файлами

Еще один интересный подход — использование цепочек стандартных утилит, которые сами по себе не выглядят подозрительно, но позволяют полноценно взаимодействовать с файлами.

• dd + more — чтение и поблочная работа с файлами.
dd — позволяет читать файл поблочно или копировать его содержимое.
more — постранично выводит результат.

• gzip + zcat — сжатие и обход анализа ответа.
gzip — сжимает файл.
zcat — выводит содержимое сжатого файла.


Важно помнить, что WAF проверяет не только HTTP request, но и HTTP response.
Именно здесь проявляется особая ценность техник изменения представления данных.

Когда используется od -c, содержимое файла преобразуется в восьмеричные коды и символьное представление. Для сигнатурных алгоритмов это уже не привычная структура /etc/passwd, а поток символов.
$ od -c /etc/passwd
0000000   r   o   o   t   :   x   :   0   :   0   :   r   o   o   t   :
0000020   /   r   o   o   t   :   /   b   i   n   /   b   a   s   h  \n

Когда применяется dd, мы работаем с файлом на уровне байтов: читаем его частями, меняем размер блока, добавляем преобразование вывода. В результате WAF видит не привычную текстовую структуру /etc/passwd, а измененный поток данных.

Shell

$ dd if=/etc/passwd bs=64 count=1 conv=ascii 
726f6f743a783a303a303a726f6f743a2f726f6f743a2f7573722f62696e
